### كيف يُحسب الـ Load

```
كل مرة يُفتح التطبيق وتظهر الخريطة = 1 Dynamic Maps load
```

| نوع المستخدم | عدد مرات فتح الخريطة/يوم | السبب |
|-------------|--------------------------|-------|
| **الراكب** | ~2-3 مرات | كل ما يفتح التطبيق ليحجز رحلة |
| **السائق** | ~1 مرة | يفتح مرة ويبقى مفتوح طول اليوم |

### السعة المجانية

```
10,000 load مجاني ÷ 30 يوم = ~333 load/يوم

مثال عملي:
  100 راكب × 2 فتحات = 200 load
   50 سائق × 1 فتحة  =  50 load
                        ─────────
                المجموع = 250 load/يوم ✅ مجاني
```

**الخلاصة: حتى 100 راكب + 50 سائق = خرائط مجانية بالكامل.**

### ⟳ الحد المجاني يتجدد كل شهر

```
كل أول الشهر → يُعاد ضبط العداد من صفر

يناير:  10,000 load مجاني ✅
        ↓ انتهى الشهر
فبراير: 10,000 load مجاني جديد ✅
        ↓ انتهى الشهر
مارس:   10,000 load مجاني جديد ✅
```

> ملاحظة: قبل مارس 2025 كان الحد $200 رصيد شهري مجمّع لكل الـ APIs.
> الآن كل API له حد مستقل يتجدد شهرياً.

## 3. تحسينات Geocoding المطبّقة (2026-05-30)

> هذه التحسينات **مطبّقة في الكود الحالي** في `useLocationPicker.ts`

### المشكلة الأصلية

```
كل مرة يسحب الراكب الخريطة → reverseGeocode() → طلب مدفوع ($5/1000)
```
الحد القديم: 5 أمتار فقط → كل حركة بسيطة = طلب جديد.

### التحسينات المطبّقة

| التحسين | قبل | بعد | التوفير |
|---------|-----|-----|---------|
| **حد المسافة الدنيا** | 5 متر | **30 متر** | ~80% طلبات أقل |
| **Idle Debounce** | 350ms | **800ms** | ~50% طلبات أقل |
| **Cache محلي للعناوين** | لا يوجد | **100 مدخل في الذاكرة** | ~30% إضافية |

### تفاصيل الكود

```typescript
// useLocationPicker.ts — سطر ~215
// 💰 تخطي إذا الإحداثيات لم تتغير (أقل من 30 متر)
haversineDistance(lat, lng, last.lat, last.lng) < 30

// 💰 Cache محلي — إذا الموقع مخزّن مسبقاً لا نطلب من Google
const cachedAddress = getGeocodeFromCache(lat, lng);

// 💰 800ms debounce بعد توقف المستخدم
idleGeocodeTimer = window.setTimeout(() => {
  requestCenterReverseGeocode("idle");
}, 800);
```

### معدل التخفيض الفعلي

| API | قبل التحسين | بعد التحسين | نسبة التخفيض |
|-----|------------|------------|-------------|
| **Geocoding** | كل 5م أو idle | 30م + debounce + cache | **~94% تخفيض** |
| **Maps Load** | لا تغيير | لا تغيير | — |
| **Directions** | لا تغيير | لا تغيير | — |

## 6. تحليل المنافس: Baly (بلي) ونظام Mapbox

### الاكتشاف الرئيسي
**Baly ليس عراقي الأصل — بل هو النسخة العراقية من Snapp (تطبيق التاكسي الإيراني الأكبر).**
وهو يعتمد بالكامل على **Mapbox SDK** للخرائط كبديل ذكي لـ Google Maps لتوفير مبالغ طائلة عند توسع الخدمة.

### مقارنة تسعير Mapbox مقابل Google Maps

| الخدمة | Google Maps Platform | Mapbox Platform | ملاحظات التوفير في RAAN |
| :--- | :--- | :--- | :--- |
| **تحميل الخريطة** | **$7.00 لـ 1,000 تحميل**<br>(كل فتح للتطبيق = تحميل خريطة) | **50,000 مستخدم نشط شهرياً (MAU) مجاناً**<br>(المستخدم يفتح الخريطة بلا حدود ويُحسب كـ 1 MAU) | **توفير 100%** في مرحلة النمو.<br>المستخدم النشط يمكنه طلب 100 رحلة شهرياً بتكلفة $0 خرائط. |
| **الـ Geocoding** | $5.00 لـ 1,000 طلب | **أول 100,000 طلب شهرياً مجاناً**<br>(ثم $0.75 لكل 1,000 طلب) | **توفير 85%** بعد نفاد الحد المجاني الضخم. |
| **تحديد المسار** | $5.00+ لـ 1,000 طلب | **أول 100,000 طلب شهرياً مجاناً**<br>(ثم $2.00 لكل 1,000 طلب) | **توفير 60%** بعد نفاد الحد المجاني. |

## 7. نظام الهجين الذكي في RAAN (أولوية المعالم - Landmark Priority)

يمتلك تطبيق RAAN بالفعل بنية تحتية مهيأة بالكامل لـ Mapbox ومحمية ضد الاستهلاك المدفوع عبر الـ Edge Function المخصصة [mapbox-proxy/index.ts](file:///d:/projects/taksi-iraqi/RAAN/raan/supabase/functions/mapbox-proxy/index.ts).

### آلية عمل Geocoding الذكي والمجاني في RAAN:
عند سحب الدبوس على الخريطة لتحديد موقع الانطلاق أو الوصول، تتم العملية كالتالي:
```
                المستخدم يسحب الدبوس
                         ↓
           فحص قاعدة بيانات معالم RAAN (Landmarks)
                         ↓
      هل توجد إحداثيات معلم معروف في حدود 500 متر؟
            ↙                             ↘
      (نعم) ✅                                (لا) ❌
  إرجاع العنوان فوراً                   طلب العنوان من Mapbox
  (مثل: "قرب جامع الدولة")              (أول 100K طلب مجاني)
  التكلفة = $0                         التكلفة = $0 (تحت الحد)
```

هذا يضمن دقة عناوين متناهية في العراق (الرمادي، الفلوجة) بالاعتماد على أسماء حقيقية تهم الراكب وبـ **تكلفة $0**.

## 9. ملاحظات تقنية مهمة

### توحيد شكل الخرائط (2026-05-30)

كانت الخرائط بثلاثة أشكال مختلفة — تم التوحيد:

| الشاشة | الملف | قبل | الآن |
|--------|-------|------|------|
| الانطلاق/الوصول | `useLocationPicker.ts` | custom styles | ✅ افتراضي Google |
| تأكيد الحجز | `useBookingFlow.ts` | dark mode ثابت | ✅ افتراضي Google |
| تتبع الرحلة | `LiveRideTracker.tsx` | dark mode ثابت | ✅ افتراضي Google |

### إصلاح Routing Adapter Race Condition (2026-05-30)

```
المشكلة: LiveRideTracker يطلب المسار قبل جهوز الـ adapter
الحل:    useEffect يراقب routingAdapter → يرسم المسار فور جهوزه
الملف:   src/components/rider/LiveRideTracker.tsx
```

### Adapter Pattern (جاهز للتوسعة)

- الكود يدعم التبديل بين Google و OSM عبر adapters في `src/lib/adapters/`
- `NominatimGeocodingAdapter` جاهز للاستخدام — فقط يحتاج تفعيل
- `useMapProvider.ts` يتحكم بالمزوّد النشط

### الـ Shared Map Cache

- `googleMapService.ts` يحتوي `getOrCreateSharedMap()` لإعادة استخدام الخريطة
- `resetSharedMapCache()` تُستخدم عند الحاجة لإعادة تهيئة نظيفة
